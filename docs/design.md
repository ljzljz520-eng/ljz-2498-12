# 编辑预览台目录服务设计

## 1. 目标与范围

为 Catalpa 编辑/预览台扩展稳定的目录（TOC）服务：

- 前端（Vue）以**稳定节点身份**在编辑树、预览页、虚拟目录列表之间同步光标与高亮；
- 后端解析文档**已保存版本**，生成锚点索引；
- 数据库维护公开链接迁移与节点沿革；
- 标题改名不改变身份；拆分标题 / 复制章节产生新身份，旧锚点进入一对多歧义；
- 旧链接不得自动跳到同名但无关的章节；
- 编辑树 / 预览页 / 服务器索引可能处于不同版本，通过**位置映射协议**协商，缺少映射时显示“待刷新”而非乱跳；
- 导出锚点使用**冻结索引**。

核心算法放在 `src/core/`，前端与 Node 服务端同构复用，保证“解析结果”只有一个事实来源。

## 2. 数据模型

### 2.1 节点 HeadingNode

文档中的每个标题都是一个节点：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定标识，形如 `n_<base36time>_<rand>`；一旦分配，改名/改层级/移动都不变 |
| `explicitId` | 标题尾部 `{#custom}` 形式的显式锚点（用户可指定） |
| `level` | 标题层级 1..6 |
| `text` | 纯文本标题（去掉 inline 标记与显式锚点） |
| `aliases` | 该节点历史上出现过的全部可读别名（slug），含当前 slug |
| `line` / `endLine` | 当前版本中的行范围（版本相关，不参与身份） |
| `fingerprint` | `level + text + 正文摘要` 的归一化哈希，仅用于 diff 启发式 |
| `revivedFrom` | 若节点由删除恢复而来，记录原 id 来源 |
| `status` | `live` / `deleted`（软删除，进入墓碑集） |
| `createdAt` / `updatedAt` / `deletedAt` | 时间戳 |
| `rev` | 最近一次相关修订号 |

### 2.2 版本

- `revision`：单调递增整数；每次保存产生新版本。
- `contentHash`：源文归一化哈希。
- 索引是**按保存版本**构建的；编辑中的未保存内容不进服务器索引。

### 2.3 位置映射 PositionMap

```jsonc
{
  "revision": 12,
  "editorRev": 13,        // 编辑树版本（可能未保存）
  "previewRev": 12,       // 预览渲染版本
  "indexRev": 12,         // 服务器锚点索引版本
  "mappings": {
    "<nodeId>": {
      "id": "n_a1",
      "editor":  { "line": 10, "offset": 0, "rev": 13, "loaded": true },
      "preview": { "line": 10, "offset": 0, "rev": 12, "loaded": true },
      "index":   { "line": 10, "anchor": "n_a1", "alias": "kai-pian", "rev": 12, "loaded": true },
      "status": "synced"  // synced | draft | index-stale | missing | deleted
    }
  }
}
```

状态语义：

- `synced`：三端版本一致，可直接跳转；
- `draft`：仅存在于编辑树（未保存），点击在编辑器内定位，不查服务器索引；
- `index-stale`：预览与索引 revision 不一致，点击显示“待刷新（索引 vN，预览 vM）”，**不跳转**；
- `missing`：虚拟列表尚未加载或目标尚未测量，触发加载/测量后重试一次，仍失败则提示“待刷新”；
- `deleted`：节点已软删除，不跳转。

映射按 `id` 寻址；slug 只作为可读别名参与“旧链接解析”，不作为跳转主键。

### 2.4 服务器存储（JSON 持久化，原子写）

- `documents`：id、当前 revision、源文、保存历史；
- `nodes`：按 docId 维护节点全量（含 deleted），即节点沿革；
- `nodeEvents`：rename / split / copy / delete / restore / level-change 沿革；
- `aliases`：`(docId, revision, alias)` → nodeId，外加“曾用别名 → 解析结果”；
- `links`：公开链接 `slug → 当前解析状态`，含迁移历史；
- `exports`：冻结索引（docId、exportId、revision、快照 nodes + aliasMap + linkBindings）。

## 3. 身份规则

### 3.1 稳定标识 vs 标题 slug

| 维度 | 标题字符串 slug | 稳定 id + 可读别名 |
| --- | --- | --- |
| 生成 | 由标题文本派生（拼音/拉丁保留、CJK 保留、小写连字符） | 首次出现时随机生成，永久不变 |
| 改名后 | 变化，旧 slug 可能被后续同名标题“占用” | id 不变，旧 slug 作为曾用别名挂到同一节点 |
| 重复标题 | 只能追加 `-2`/`-3`，无法区分身份 | 每个节点各自独立 id；slug 仅作展示别名，同样加序号 |
| 拆分/复制 | 无法表达一对多 | 新节点得新 id，旧 id 标记 split 歧义 |
| 冲突消解 | 同版本首次出现者保留裸别名，其余 `-2/-3`；显式锚点冲突同样加后缀并记录 warning | id 空间随机 + 建表唯一约束兜底 |
| 撤销 | 删除前 slug 已被新同名占用则无法回退 | 墓碑恢复沿用原 id 与全部历史别名 |

**结论**：内部同步与跳转一律使用稳定 id；slug/别名只用于人类可读 URL 与旧链接兼容。

### 3.2 身份判定（reconcile，见 `heading-diff.js`）

基于行级 LCS 对旧标题序列与新标题序列分块（hunk）：

1. **相等区**：标题文本与层级相同 → 身份沿用（移动不发生在纯文本视角，跨设备移动需显式锚点或服务器沿革）。
2. **显式锚点优先**：标题含 `{#x}`，若 `x` 已在沿革中绑定某 id，则继续绑定到该 id；同版本重复显式锚点视为复制 → 新 id + `copy` 事件。
3. **单旧 → 单新（1:1 替换块）**：相似度 ≥ 阈值（编辑距离归一化）→ 同一身份，产生 `rename` / `level-change` 事件，旧 slug 并入别名。
4. **单旧 → 多个新块（1:N）**：判定为**拆分**。旧节点 `deleted(split)`，新节点全部获得**新 id**；旧 id 的锚点解析结果变为 `ambiguous:[...]`，不自动选择。
5. **无旧 → 多个新块（0:N）**：若其中某个新节点与某现存/刚删除节点文本一致且处于复制位置，则为**复制**（新 id + `copy`，来源记录在沿革）；其余为普通新增。
6. **删除与恢复**：多旧 → 0 新块中的节点进入墓碑集。再次出现相同标题时，仅当**相邻结构证据**吻合（前后存活兄弟与墓碑记录的 before/after 相同；孤立首标题允许锚点位置匹配）才判定为 `restore` 并沿用原 id；否则视为无关新章节（新 id）。多个同指纹墓碑同时存在时不恢复，避免歧义。
7. **改层级**：`# A` → `## A` 是 `level-change`，id 不变。

### 3.3 旧链接解析（resolveAnchor）

输入旧锚点与“当前索引 + 沿革”，返回：

- `ok`：唯一定位（通过节点 id 或该节点名下的曾用别名）；
- `renamed`：别名曾属于且只属于一个现存节点 → 跟随，但返回 301 风格状态供客户端提示“已改名”；
- `ambiguous`：拆分等一对多 → 展示候选列表，**不自动跳**；
- `gone`：节点已删除且无候选；
- `foreign`：旧别名已被一个**身份不同**的同名新标题占用 → 不跳，提示“该链接属于已删除章节，当前同名章节内容无关”。

核心保证：**曾用别名的归属永不重新分配给其他 id**。

## 4. 位置映射协议

- 编辑树每次变更（防抖后）本地跑解析+reconcile，得到 `editorRev` 的节点与行位；
- 预览渲染完成并测量标题 DOM 后得到 `previewRev`；
- `indexRev` 来自 `GET /api/docs/:id` 返回的服务器保存版本；
- `buildPositionMap` 合并三方位置，逐节点计算状态；
- 点击目录：
  1. `synced` → 先在编辑器定位（记录会话游标位置 `tocSession.lastAnchor=id`）；
  2. 从编辑器返回预览时，凭 `lastAnchor` + 当前 PositionMap 回到同一内容（测量/重排后重新取坐标）；
  3. `draft` → 仅编辑器内定位；`index-stale`/`missing` → 显示“待刷新”内联提示，不乱跳；
- 虚拟列表：未渲染节点 `loaded=false`，点击先 `ensureVisible(id)` 再测量重试一次。
- 字体重排（字体加载、容器尺寸变化、图片占位变化）：监听 document.fonts.ready 与 ResizeObserver，使旧坐标失效并以**节点 id**重新测量，而不是记住像素值。

## 5. 跨设备并发

保存使用 CAS：`PUT /api/docs/:id` 必须带 `baseRevision`。

- 服务器发现 `baseRevision < 当前 revision` → 409，返回服务器最新源文、节点沿革与两份内容的 reconcile 结果；
- 客户端不静默覆盖：提示“远端有新版本”，由映射协议决定哪些节点仍可定位；
- “同时改层级”等场景下身份以显式锚点 / 沿革为准，层级差异展示为 `level-change` 事件。

## 6. 冻结导出

`POST /api/docs/:id/exports` 在指定 revision 上构建冻结快照：节点、别名表、公开链接绑定关系全部复制为不可变数据。
导出 HTML 中：

- 标题 `id` 取冻结时的稳定 id；
- href 使用 `/p/<docSlug>/<exportId>#<anchor>`，永久路由到该冻结版本；
- 即使 live 文档后续改名、拆分、删除，导出链接解析始终以冻结索引为准。

## 7. 验收场景（对应 test/ 目录）

1. 重复标题：同标题出现 3 次 → 3 个不同 id；裸别名归首个，其余 `slug-2/-3`；旧链接跟随身份而非名字。
2. 删除后恢复：删除后 Ctrl+Z 风格恢复 → 原 id、原别名、公开链接重新有效。
3. 虚拟列表未加载节点：`loaded=false` 时点击不误跳，ensureVisible + 重试后定位。
4. 字体重排：坐标全部失效后凭 id 重新测量仍定位到同一标题。
5. 跨设备同时改层级：409 + 合并后身份不变，记录 level-change。
6. 点击目录到编辑位置再返回预览：`tocSession.lastAnchor` 保证同一内容。
7. 拆分标题：旧锚点变 ambiguous，候选即新节点；不自动跳。
8. 复制章节：粘贴同名章节 → 新 id + copy 事件；旧链接不跳到复制品。
9. 同名无关章节：旧章节删除后新建同名章节 → foreign，不自动跳。
10. 导出锚点：冻结后再大改文档，导出链接仍按冻结索引解析。
